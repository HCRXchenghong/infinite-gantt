# infinite-gantt

悦享e食平台 · 项目时间线甘特图

一个**零依赖**的全栈小项目：前端是可视化甘特图，后端是一个纯 Node.js 原生 HTTP 服务，附带带鉴权的后台管理界面。用于展示「悦享e食」智能餐盘平台按**硬件研发 / 软件开发 / 平台运营**三条线并行推进的项目里程碑。

不用任何框架、不用任何 npm 包，`node server.js` 直接跑起来。

## 效果与功能

### 前端甘特图

| 功能 | 说明 |
|---|---|
| **按负责人分道** | 每个部分内，负责人相同的事件共用一行，不同负责人各占一行，左侧列出部分名与每道负责人 |
| **4 档日期粒度** | 日 / 周 / 月 / 季度 自由切换，日视图每天 72px，精确到每一天 |
| **今天贴最左** | 刷新后自动横向滚动，让「今天」的红色竖线停在可视区最左侧；向左滚动可回看历史 |
| **粒度切换吸附** | 切换档位时左边缘自动对齐到所属单位起点（周一 / 月 1 日 / 季首日），不会出现半截格子 |
| **左列常驻** | 横向滚动时「所属部分」列始终钉在左边，不会滚出视野 |
| **事件详情** | 点击条形查看起止时间、持续天数、负责人、详细说明 |
| **自适应铺满** | 行高按可用高度平均分配，占满整屏；窗口尺寸变化自动重绘 |

### 后台管理

| 功能 | 说明 |
|---|---|
| **左侧栏布局** | 导航在「事件管理」「人员名单」两个页面间切换 |
| **弹窗式编辑** | 新增 / 编辑事件共用一个弹窗，支持 Esc、点遮罩、点取消关闭 |
| **负责人自动补全** | 输入姓名回车即成为标签，候选来自人员名单，用过的名字自动进名单 |
| **人员名单管理** | 可预先批量录入人员，也可移除（仍被事件引用的名字会自动保留） |
| **并发冲突校验** | 同一部分内同一时间并行的事件数不能超过 2 个，超出会拒绝保存并提示原因 |

## 快速开始

### 环境要求

- **Node.js 14 或更高**。只用到 `http` / `fs` / `path` / `crypto` 四个内置模块，没有任何 npm 包，所以不需要 `npm install`。

### 配置账号密码

源码里**没有**内置任何真实密码。第一次运行前先配置你的后台账号：

```bash
cp .env.example .env
# 编辑 .env，填入 ADMIN_USER 和 ADMIN_PASS
```

`server.js` 启动时会自动读取同目录下的 `.env`，不需要额外的命令行参数。

> 如果你没有配置，服务不会拒绝启动，而是**随机生成一个临时密码并打印在控制台**（仅本次启动有效）。这是为了避免出现"空密码可登录"的漏洞。

### 启动

```bash
# 1. 克隆仓库
git clone https://github.com/HCRXchenghong/infinite-gantt.git
cd infinite-gantt

# 2. 配置账号（见上一节）
cp .env.example .env && vim .env

# 3. 无需安装依赖，直接启动
npm start
# 或
node server.js
```

启动后终端会打印：

```
悦享e食平台时间线已启动: http://localhost:3000
后台管理: http://localhost:3000/admin-manage
```

- 前端甘特图：http://localhost:3000
- 后台管理：http://localhost:3000/admin-manage

首次启动会自动生成 `data.json`，内含 8 条示例里程碑数据（2026 年全年）。

### 换端口

```bash
PORT=8080 node server.js
```

## 配置

全部配置通过环境变量（或 `.env` 文件）提供，源码中不保存任何敏感信息。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ADMIN_USER` | 无 → `admin` | 后台登录用户名 |
| `ADMIN_PASS` | 无 → **随机生成** | 后台登录密码，未配置时每次启动都不同，并打印到控制台 |
| `PORT` | `3000` | 服务监听端口 |

真实环境变量优先级高于 `.env` 文件，所以也可以内联传入：

```bash
ADMIN_USER=myname ADMIN_PASS=mypassword node server.js
```

或者临时换端口：

```bash
PORT=8080 node server.js
```

> `.env`、`data.json`、`bans.json` 均已加入 `.gitignore`，不会被提交。

### 部署注意

会话 token 保存在**进程内存**里，服务重启即全部失效、需要重新登录；`data.json` 与 `bans.json` 则持久化在磁盘。所以：

- 单机单进程直接跑没问题。
- 如果要多进程 / 多实例（PM2 cluster、多台机器负载均衡），需要自行把 `SESSIONS` 换成 Redis 之类的共享存储，并把 `data.json` 换成数据库，否则各实例数据不一致。
- 部署在反向代理之后时，请确保代理正确透传 `X-Forwarded-For`（见[安全设计](#安全设计)）。

## 项目结构

```
infinite-gantt/
├── server.js           # 后端：HTTP 服务、静态资源、API、鉴权、封禁、并发校验
├── package.json        # 仅一个 start 脚本，零依赖
├── .env.example        # 环境变量示例（复制为 .env 后填写）
├── .gitignore
│
├── public/             # 前端甘特图（公开访问）
│   ├── index.html
│   ├── style.css
│   └── app.js          # 渲染引擎：分道、4 档粒度、今日线、滚动吸附
│
├── admin/              # 后台管理（需登录）
│   ├── index.html      # 左侧栏布局 + 事件弹窗
│   ├── style.css
│   └── app.js          # 登录、事件 CRUD、负责人标签、人员名单
│
├── .env                # 你的本地配置（自动生成/gitignore，不提交）
├── data.json           # 运行时数据（自动生成，不提交）
└── bans.json           # 登录失败封禁记录（自动生成，不提交）
```

### 路由约定

后台挂在 `/admin-manage` 路径下（**不是** `/admin`，避免被扫描器轻易命中），静态资源用绝对路径 `/admin-manage/xxx` 引用；其余路径一律走 `public/` 目录。

## 数据模型

`data.json` 结构：

```json
{
  "events": [
    {
      "id": 1,
      "title": "样机方案设计",
      "part": "硬件研发",
      "start": "2026-01-05",
      "end": "2026-02-20",
      "desc": "智能餐盘硬件样机的整体方案设计、元器件选型与原理图评审。",
      "owners": ["张三", "李四"]
    }
  ],
  "roster": ["张三", "李四"]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 自增主键 |
| `title` | string | 事件标题（必填） |
| `part` | string | 所属部分，取值 `硬件研发` / `软件开发` / `平台运营`（必填） |
| `start` | string | 开始日期 `YYYY-MM-DD`（必填） |
| `end` | string | 结束日期 `YYYY-MM-DD`，**含当天**（必填） |
| `desc` | string | 详细说明（可选） |
| `owners` | string[] | 负责人列表，前端按此分道（可选） |
| `roster` | string[] | 人员名单 = 手动预置 ∪ 所有事件用过的负责人 |

> **旧数据兼容**：如果 `data.json` 是早期的纯事件数组，首次读取时会自动迁移为上述对象结构。
>
> **首次启动**：内置的 8 条示例数据 `owners` 都是空数组，所以甘特图上它们会全部归入「未分配」这一行。在后台给事件加上负责人后，会自动按负责人拆分到各自的行。

## API 接口

### 公开（无需登录）

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/data` | 返回 `{ events, roster }`，前端甘特图使用 |
| `GET` | `/api/events` | 仅返回事件数组 |
| `GET` | `/api/auth?t=<token>` | 校验会话是否有效，返回 `{ ok }` |
| `POST` | `/api/login` | 登录，body `{ user, pass }`，成功返回 `{ ok, token }` |

### 需要登录（请求头带 `Authorization: Bearer <token>`）

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/logout` | 注销当前会话 |
| `POST` | `/api/events` | 新增事件 |
| `PUT` | `/api/events` | 修改事件，body 需带 `id` |
| `DELETE` | `/api/events?id=<id>` | 删除事件 |
| `POST` | `/api/roster` | 批量添加人员，body `{ names: [...] }` |
| `POST` | `/api/roster-remove` | 从名单移除某人，body `{ name }` |

### 响应示例

```jsonc
// 登录成功
{ "ok": true, "token": "b98cdb3564f0677fb1912f46096bfdaaf8c60a12fbd731df" }

// 登录失败（累计 3 次前）
{ "ok": false, "error": "用户名或密码错误（剩余 2 次机会）" }

// 并发冲突
{ "ok": false, "error": "「硬件研发」同一时间进行的事件不能超过 2 个（当前会导致 3 个并行），请调整时间" }
```

## 安全设计

### 鉴权

- 登录成功签发 **随机 token**（`crypto.randomBytes(24)`），保存在服务端内存的 `Map` 中，**12 小时过期**。
- 密码比对使用 `crypto.timingSafeEqual`（先各自 SHA-256 摘要再比对），避免时序侧信道。
- 所有写接口（增删改事件、改名单）都要求有效 token，未登录返回 `401`。
- 服务重启会清空会话，需要重新登录。

### 登录失败封禁

按客户端 IP 累计失败次数，记录持久化在 `bans.json`：

| 累计错误次数 | 处罚 |
|---|---|
| 1 ~ 2 次 | 仅提示剩余机会 |
| **3 次** | 封禁该 IP **12 小时** |
| **4 次** | **永久封禁**该 IP |

细节：

- 被封禁的 IP 即使输入正确密码也会被拒绝。
- **临时封禁期间输入正确密码可立即解除**（避免管理员自己误输把自己锁死）；但若继续输错则升级到第 4 次，触发永久封禁。
- 永久封禁只能手动删除 `bans.json` 中对应记录来解除。
- IP 取值优先 `X-Forwarded-For` 首段，兼容 `::ffff:` 前缀与 IPv6 回环地址。

> ⚠️ 如果你部署在反向代理（Nginx / Caddy / 云平台）之后，请确保代理正确透传 `X-Forwarded-For`，否则所有请求会被识别为同一个 IP，封禁会误伤全体访客。

### 其它

- 静态文件服务做了**目录穿越防护**：解析后的绝对路径必须落在 `public/` 或 `admin/` 目录内，否则返回 `403`。
- 请求体大小上限 1 MB，超出直接断开连接。
- 前端**不显示任何后台入口**，后台地址需要自己知道。
- 事件详情中的 `desc` 输出前做了 `<` 转义。

## 常见问题

**Q：刷新后看不到「所属部分」那一列？**
A：请强制刷新（`Cmd + Shift + R` / `Ctrl + F5`）清掉浏览器缓存的旧 JS/CSS。

**Q：保存事件时提示并发冲突怎么办？**
A：这是设计如此——同一部分（如硬件研发）在同一时间段最多允许 2 个事件并行。把新事件的起止时间错开，或改到其它部分即可。上限可在 `server.js` 顶部的 `MAX_CONCURRENT_PER_PART` 调整。

**Q：我把自己 IP 封了，怎么解？**
A：删掉 `bans.json` 文件（或删除其中对应的 IP 记录），然后重启服务。

**Q：数据存在哪里？会丢吗？**
A：全部存在 `data.json` 文件里，直接改文件也可以。该文件已被 gitignore，不会随仓库提交，也不会被别人的改动覆盖。

**Q：能加更多「部分」（线）吗？**
A：可以，但要同时改三处，否则前后端会对不上：
1. `server.js` 顶部的 `PARTS` 数组（后端校验白名单）
2. `public/app.js` 顶部的 `PARTS` 数组（前端渲染顺序与配色）
3. `admin/index.html` 里 `<select id="part">` 的 `<option>` 列表

**Q：为什么是零依赖？**
A：本项目规模小（约 1500 行），用 Node 原生 `http` / `fs` / `crypto` 足够，省去安装、漏洞扫描与版本维护成本，克隆下来就能跑。
